# 原始需求文档

> 本文档为项目原始需求，所有开发工作以此为准。

---

## 一、项目概述

需要做一个可接入图片、视频生成 API 的网页平台，通过调用火山方舟的 API 使用以下模型进行视频、图片生成：

| 类型 | 模型名称 | 模型ID |
|------|---------|--------|
| 视频生成 | Seedance 2.0 | `doubao-seedance-2-0-260128` |
| 视频生成 | Seedance 2.0 Fast | `doubao-seedance-2-0-fast-260128` |
| 图片生成 | Seedream 5.0 Lite | `doubao-seedream-5-0-lite-260128` |
| 图片生成 | Seedream 4.5 | `doubao-seedream-4-5-260128` |

**前端基础**：已有静态 HTML 构建产物（Vue 3 项目），需要根据该产物进行 Vue 3 + TypeScript 重构。

**Git 仓库**：项目初始化时必须建立相应的 Git 仓库。

---

## 二、用户功能需求

### 2.1 账号体系

1. **用户只能通过账号登录平台，不能注册账号**
2. **严格的数据隔离**：每个用户只能查看/操作自己的数据
   - 只能查看自己的任务状态
   - 只能取消自己的任务
   - 只能查看自己的历史任务
   - 只能下载自己任务中生成的视频或图片

### 2.2 生成模式

用户可选择两种生成模式：
- **图片生成**：调用 Seedream 系列模型
- **视频生成**：调用 Seedance 系列模型

### 2.3 任务执行流程

1. 选择生成模式（图片/视频）
2. 选择平台提供的模型
3. 选择模型支持的输出参数（分辨率、画面比例、时长等）
4. 输入提示词（prompt）
5. 上传参考文件（图片/视频/音频）
6. 点击生成按钮执行任务
7. 查看任务状态
8. 任务完成后预览/下载生成的文件
9. 可随时取消进行中的任务

### 2.4 参考文件规则

- 视频生成模型支持：图片、视频、音频作为参考输入
- 图片生成模型支持：图片作为参考输入
- 用户上传文件时，需要判定文件是否符合对应模式以及模型的上传规则
- 输入框中输入 `@` 字符可引用已上传的文件

## 三、平台模块需求（10个模块）

### 3.1 模型管理模块（模型配置类）

**职责**：配置 API 以及模型功能

**功能要求**：
- 兼容火山方舟的 API 并可获取调用模型
- 可配置多个 API 以及多个平台可调用的模型
- 配置 API 支持的总并发数量
- 配置模型支持的并发数量
- 按模型配置对应的调用方法
- 按模型配置所支持的功能
- 按模型配置可支持的识别文件类型
- **后续需兼容更多平台的 API 格式**
- 可被其他模块调用

### 3.2 文件管理模块（文件管理类）

**职责**：管理用户上传的图片、视频、音频文件，以及模型输出的视频、图片文件

**功能要求**：
- 将用户上传的文件重新命名，保证其唯一性
- 存储在平台本地文件系统中
- 可被其他模块调用

### 3.3 任务文件处理模块（文件管理类）

**职责**：处理上传给模型的文件

**功能要求**（两种处理方法）：
1. **Base64 转换**：将用户上传的图片、音频、视频转成 Base64 格式，存储回文件管理模块
2. **TOS 上传**：将用户上传的图片、视频、音频通过火山引擎的 API 上传至对象存储服务 TOS 中，返回对应文件的公网 URL 以及文件的状态（未上传、上传中、已上传），并将文件对应的公网 URL 返回到文件管理模块中

> **TOS 功能定位**：TOS 仅用于将文件转换为公网 URL 供火山方舟 API（Seedance/Seedream）读取参考文件，**不做备份用途**。平台的主文件存储始终在本地文件系统。

### 3.4 文件下载模块（文件管理类）

**职责**：下载模型生成的文件

**功能要求**：
- 下载模型生成的文件至文件管理模块（本地存储）

### 3.5 用户文件上传模块（文件管理类）

**职责**：向用户交付下载的文件

**功能要求**：
- 在用户发起下载任务时，将用户下载的文件上传/发送给用户

### 3.6 前端文件调用模块（文件管理类）

**职责**：响应前端文件请求

**功能要求**：
- 接受前端的请求
- 将前端需要显示或预览的文件发送给前端

### 3.7 任务生成模块（任务管理类）

**职责**：分配任务 ID 并打包任务内容

**功能要求**：
- 分配唯一的平台任务 ID
- 打包任务内容
- 发起任务至任务队列模块
- 当用户选择生成模式、选择模型、输入提示词、上传文件、开始执行任务后：
  - 为任务分配唯一的平台任务 ID
  - 根据用户选择的生成模式和模型
  - 整合用户输入的提示词和上传的文件的公网 URL 或 Base64 格式（通过调用文件管理系统获取）
  - 进入任务队列
- 可调用其他模块

### 3.8 任务队列模块（任务管理类）

**职责**：管理任务队列与状态轮询

**功能要求**：
- 接收任务生成模块的任务加入队列
- 根据任务信息选择模型
- 根据模型的并行数量调用模型（并行数量通过模型管理模块获取）
- **超出并行数量的任务在队列中等待**
- **轮询进行中的任务状态**（默认 30 秒轮询一次）
- **每个任务的轮询相互独立**
- 若 API 返回了任务完成的通知则结束对该任务的轮询
- 获取与平台任务 ID 对应的模型 API 分配的远端任务 ID
- 获取任务状态
- 取消任务
- 接收模型生成的视频或图片
- 将已完成的、失败的、取消的任务信息发送至历史任务模块
- 调用文件下载模块下载模型生成的文件，下载至文件管理模块

### 3.9 历史任务模块（任务管理类）

**职责**：存储用户历史任务信息

**功能要求**：
- 存储每个用户的历史任务
- 任务信息包含：时间、调用模式、调用模型、任务状态、用户上传的文件名称、模型生成的文件

### 3.10 用户管理模块（用户管理类）

**职责**：管理账号与用户数据

**功能要求**：
- 管理账号的创建（**用户不能自行注册，只能由管理员创建**）
- 管理用户的账号等级（分为 **admin、leader、user**）
- 管理用户账号上的数据

## 四、前端需求

### 4.1 框架

- **采用 Vue 3 + TypeScript 框架**

### 4.2 内容结构

- **单页设计**，分为侧栏和右侧主内容
- **深色极简风**，注意风格统一与排版美观实用

#### 侧栏布局（从上至下）

1. **平台 logo 或名称**（靠上对齐）
2. **导航菜单**（居中）：生成（首页）、历史、资产
   - 管理不显示在 user 的页面中
   - 每个内容显示为一个图标加下方的文字名称
3. **用户名、登出按钮**（靠下对齐）

### 4.3 生成页面（主内容区-生成）

#### 4.3.1 框架结构

- 分为**输入悬浮框**与**生成内容区**
- 悬浮框位于右侧内容区底部（与内容区下边缘保持一定空隙）
- 悬浮框上边缘以上到内容区最上方为**对话内容区**
- 左上方有一个**新建会话**按钮
- 生成区可以滚动
- 每次打开时都显示为关闭前的页面

#### 4.3.2 生成内容区 - 任务块

每次用户点击生成按钮则：
- 生成一个任务块
- 同时清空输入悬浮窗
- **若输入悬浮窗内没有输入提示词，则不生成任务块同时提示提示词为空**

**每个任务块内容（从上至下）**：
1. 用户输入的提示词
2. 用户上传的文件
3. 用户选择的生成模式、选择的模型、生成文件参数（例如：视频时长，画面比例，分辨率，帧率）
4. 模型生成的图片或视频文件的缩略图
   - 如果有多个，则显示为一行或多行，**每行不超过 4 个**
   - 若文件未生成，则显示任务状态
   - 任务被取消或者出现错误，则在显示文件的位置显示任务状态和错误码
5. **复用按钮**（点击后自动将对应任务块中的模式、模型、提示词、文件重新填入到输入悬浮框中）
6. **任务结束时间**（与复用按钮位于同一行，属于次要功能，大小要比其他内容小且不能太明显）

#### 4.3.3 输入悬浮窗

内容（从上至下）：
1. 上传的文件的缩略图（文件分为视频、图片、音频三种）
2. 用户输入的提示词
3. 模式选择、模型选择、生成参数、生成四个按钮
   - 模式选择、模型选择、生成参数三个按钮在栏的左侧
   - 生成在右侧
   - 点击后会出现选择的栏

**`@` 文件引用功能**：
- 在用户输入 `@` 字符时，在该字符后出现选择文件的栏
- 例如用户上传了多张图片，在输入 `@` 后出现 "图片1" "图片2" "图片3"
- 图片 1、2、3 分别对应上传的先后顺序，音频、视频文件同理
- 选择对应的文件后，需要在 `@` 字符前显示对应文件的缩略图
- 缩略图在该位置需要和文字大小一致
- 如果音频文件不显示缩略图

#### 4.3.4 模型联动与文件校验

- 视频生成模型只能选择视频模型，只能选择对应视频模型支持的生成参数和功能
- 图片生成模型同样如此
- 用户上传文件时，需要判定文件是否符合对应模式以及模型的上传规则

### 4.4 历史页面（主内容区-历史）

#### 4.4.1 框架结构

- 分为历史列表和搜索栏
- 历史列表位于主内容区中央，上下可滚动
- 搜索栏位于主内容区右上角

#### 4.4.2 历史列表

- 当没有检索时，按照时间顺序（**最晚生成的任务在最下方**）列出用户已结束的任务块
- 包含已完成和失败的任务
- 在任务块上方标出：任务开始时间、任务结束时间、复用按钮
- 复用按钮功能同"生成"一致，但点击后需要**跳转回"生成"页面并填充内容**

#### 4.4.3 搜索栏

- 可通过检索**具体到小时的时间**来筛选任务
- 当开始检索时，历史列表内被替换为符合检索条件的任务块

### 4.5 资产页面（主内容区-资产）

#### 4.5.1 框架结构

- 分为资产列表和搜索栏
- 资产列表位于主内容区中央，上下可滚动
- 搜索栏位于主内容区右上角

#### 4.5.2 资产列表

- 当没有检索时，按照时间顺序（**最晚生成的资产在最下方**），列出生成的图片或视频资产的缩略图

#### 4.5.3 搜索栏

- 可通过检索**具体到小时的时间**来筛选任务
- 当开始检索时，资产列表内被替换为符合检索条件的文件缩略图

### 4.6 预览窗口

当用户点击图片或视频文件缩略图后，显示预览窗口。

**预览窗口元素**：
- 右上角：**关闭弹窗按钮**（点击弹窗外也能关闭弹窗）
- 关闭按钮左侧：**下载按钮**

**图片预览**：
- 可通过鼠标滚轮放大缩小（**滚轮向上滚动为缩小**）
- 放大缩小后可按住鼠标左键拖动图片

**视频预览**：
- 点击后视频直接开始播放
- 预览窗口下方需要有：开始/暂停按钮、播放进度条、音量控制条

### 4.7 文件缩略图规范

- **图片或视频文件**：显示为缩略图时需要**维持原画面比例**
- **音频文件**：显示为 **1:1 的小图标**，图标内容为对应格式的文字
- **鼠标悬停**：需要显示对应的文件名称，缩略图左下角需要显示下载按钮
- **输入悬浮框中的缩略图**：缩略图右上角需要有**删除文件的按钮**

## 六、技术约束

1. **数据库**：优先使用 SQLite
2. **缓存**：使用 Redis
3. **文件存储**：本地文件系统为主存储
4. **TOS 定位**：仅用于将文件转为公网 URL 供火山方舟 API 读取，**不做备份用途**
5. **并发控制**：按模型配置并行数量，超出部分排队等待
6. **轮询策略**：默认 30 秒轮询一次，每个任务独立轮询
7. **用户隔离**：严格的用户级数据隔离，任何操作必须验证归属
